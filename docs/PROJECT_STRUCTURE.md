## Runtime data (`%APPDATA%\Jarvis`)

Electron's `app.getPath('userData')` resolves to `%APPDATA%\Jarvis` (from `productName`) and is passed to the backend as `JARVIS_DATA_DIR`. Dev runs and the installed app use the same folder.

| Path | Content |
|---|---|
| `jarvis.db` (+ `-wal`, `-shm`) | SQLite database (see [DATABASE_SCHEMA.md](DATABASE_SCHEMA.md)) |
| `logs\backend.log` | Backend log, rotating at 2 MB, 3 backups, secrets redacted |
| `logs\backend-console.log` | Backend stdout/stderr captured by Electron (rotated to `.1` above 5 MB) |
| `models\` | Optional model override; `Paths.model_file()` checks here first, then `resources\models` |
| `browser-profile\` | Dedicated Playwright profile (cookies and logins for the automation browser) |
| `screenshots\` | `browser_screenshot` output |
| Electron/Chromium files | Electron's own userData content |

Secrets are not stored here. They live in Windows Credential Manager under the service name `Jarvis Desktop Agent`.

Resources directory: in dev this is `<repo>/resources`; packaged it is `process.resourcesPath`, containing `backend\`, `models\` and `icons\`.
